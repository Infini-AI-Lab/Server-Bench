# Serving-system evolution

Follow the rapid loop in AGENT_TASK.md: hypothesis → small edit → real GPU profile
+ protocol probes + your own correctness checks + lightweight replay gate → keep
or revert → checkpoint.
Preserve weights, tokenizer, dtype, model equations, request semantics and the
task's declared workload. Optimize execution, not benchmark answers.

Read [vLLM](references/13-vllm-v1.md) and [SGLang](references/14-sglang-runtime.md)
to extract applicable mechanisms. Establish the model/workload/hardware boundary before choosing an
architecture. Framework overhead, kernels, batching, admission, overlap,
parallelism, communication, compilation, memory lifetime, KV reuse, exact
speculation, routing and streaming are options, not a mandatory architecture.
[Optimization techniques](references/17-optimization-techniques.md) is a menu,
not a checklist. Invent alternatives when measurements justify them.

## Evidence and cadence

Use torch.profiler, nsys or ncu on actual candidate GPU execution for each design
change. CPU-only/client-only traces do not count. Microbenchmarks cover both
short requests and near-maximum permitted input lengths, including decode and
changed state/shape boundaries. Keep raw evidence, input/output counts, source
identity and quantitative before/after observations below /workspace/agentx.

[Design review](references/18-design-review.md) partitions responsibility into
deployment, semantics, state_memory, scheduling, host_io, device_compute and
topology_transfer. Update affected invariants and bounds, reusing still-valid
unchanged evidence. The scripts check bounded evidence, not universal correctness.

[run_trial.py](scripts/run_trial.py) freezes the same filtered source that
publication delivers and cold-starts it. `--through correctness` runs the two
fast gates. There is no independent reference-canary requirement.
[profile_candidate.py](scripts/profile_candidate.py) captures native GPU work;
[design_review.py](scripts/design_review.py) binds design, profile and trial.

Use uninstrumented 1800s AgentX windows periodically, not per edit.
`run_trial.py --stage full --design-evidence RECEIPT` checks performance and
replay; `--through full` also checks protocol/context. Neither is a complete
final-verdict test.

**Complete at least one `./full-test --wait` during every evolve cycle.** Stop
your own GPU work first. It uses the actual harness deployment and full verifier,
including the post-timing model-fidelity audit, on public development traffic.
Inspect /workspace/agentx/full-tests/ and reserve time to repair and retest.
Unsupported backends report a blocker rather than a false pass.
Private final validation remains independent. No diagnostics or profiling belong
in timed serving; the full verifier audits model fidelity after timing ends.

## Delivery and continuation

Read DELIVERY_POLICY.json and DELIVERY_REPORT.json. The filter excludes more than
.venv: binary/data assets, build products, evidence, archives, hidden entries,
symlinks, oversized files and excessive nesting. Declare dependencies in
runtime_resources.json; excluded products must be generated by delivered source
during serve.sh before readiness. Test the actual bundle, not cache-rich workspace
state. Missing/stale evidence or missing resources are development failures.

./checkpoint saves experiments asynchronously without a gate prerequisite.
Timebox selects the last working tree; ./promote VERSION is an intentional rollback.
Keep a verified fallback. Use ./clock to budget full tests and repairs. When a
large experiment no longer fits, continue useful bounded coverage, profiling or
dependency checks rather than idling or shipping untested changes.
